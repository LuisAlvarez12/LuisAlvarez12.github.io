# Import Portfolio App

The only required user input is an App Store link. Complete the local website update without asking for a title, slug, assets, or confirmation of the import. Default to the US English storefront, as requested for this project. Honor an explicit request for a different locale; the current importer only supports US English and must be adapted before using another locale.

## Project and app identity

The project root is three directories above this skill folder. Work there, not in an unrelated current directory. Read the root `README.md`, `js/apps-registry.js`, and the relevant existing app config. Consult `apps/README.md` only for additional schema details. This is a static HTML/CSS/JavaScript site with no build step.

Validate that the input is an HTTPS `apps.apple.com` app link, and extract its numeric `id`. Normalize the import URL to `https://apps.apple.com/us/app/idAPP_ID?l=en-US`; preserve the numeric ID regardless of the supplied title or region.

Match the numeric ID against `appStoreUrl` in `apps/*/config.json` before choosing a slug. Reuse a matching app's folder even if its App Store name has changed. For a new app, choose a concise lowercase hyphenated slug from its name. If the slug belongs to a different ID, append the numeric ID. Do not add duplicate registry entries or reorder existing apps.

## Import

Use the maintained project scripts rather than duplicating their extraction logic:

- `scripts/import-app.sh`: metadata, image downloads, config creation, and registration.
- `scripts/storefront-assets.py`: extracts and validates the US English storefront artwork.

The legacy iTunes Lookup API can return different screenshots even with `country=us`. The storefront's `product_media_phone_` screenshot set, order, original dimensions, and icon are authoritative for this site's iPhone presentation. Do not silently fall back to Lookup API artwork, another locale, or another device's screenshots. If the requested storefront cannot be read, report the concrete blocker.

Check the working tree first. Stage the import in a temporary copy of the project's `scripts/`, `apps/`, and `js/apps-registry.js` so a failed download or config generation cannot partially overwrite the website. Copy the current local files, including uncommitted edits. Since the importer locates its root relative to its own script, invoke the copied script in that temporary project. Do not copy the legacy `_site` or cache directories.

Run the copied importer with the normalized URL and resolved slug. For an existing app, the user's import request authorizes answering the script's overwrite prompt with `y`:

```bash
./scripts/import-app.sh "$app_url" "$app_slug" <<<'y'
```

Use validated URL/slug values and proper shell quoting. On failure, inspect the error and correct a clear local scripting issue when possible; otherwise leave the real project unchanged and explain what failed.

## Complete the app data

Review the staged `apps/SLUG/config.json` before copying results back:

- Preserve an existing app's custom subtitle, features, accent color, legal content, support URL, and other custom fields. Refresh its store metadata and assets.
- For a new app, write a concise subtitle and accurate feature summaries from the listing. Avoid invented functionality or pricing claims. Use the site's blue `#2563eb` unless an app-specific color is already established.
- For a new Rezonating Apps app, set `supportUrl` to `support.html`. Preserve an existing support destination.
- The importer generates generic terms/privacy placeholders for new apps. They are not the app's published policies. Replace them with the app's actual published policies when available from its linked official pages; otherwise remove the placeholder sections, leave empty `sections` arrays, and report that legal content still needs to be supplied. Do not invent legal or data-collection claims or rewrite existing policies.
- Set `coverImage` to the first imported screenshot and keep the screenshot order from the storefront. Remove only obsolete numbered screenshots generated by an earlier import of this app; retain custom images.

Validate the staged result, then copy the target app folder and the updated registry into the actual project. Preserve other app folders, unrelated edits, support pages, and site styling.

## Verify and deliver

Check that the JSON parses, the slug is registered exactly once, all referenced image files decode with nonzero dimensions, and the screenshot count/order matches the storefront. Confirm preserved custom fields against the pre-import config and inspect at least the first screenshot visually to catch wrong artwork.

Serve the project with `python3 -m http.server 8000 --bind 127.0.0.1` if no preview is running. Verify the homepage card and `app.html?id=SLUG`, including icon, screenshots, and support link. Refresh an existing preview after replacing assets. Run `git diff --check` and inspect the scoped diff.

Report the app name, screenshot count, and preview location concisely. Note any missing legal content and whether the changes are local or deployed. Creating or refreshing a listing does not itself authorize pushing, publishing the website, or changing App Store Connect; do those only when the user requests them.
